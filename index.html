GETTING STARTED

Quick start

Without an audience or API key, the API serves the public feed. Use /v1/incidents for REST and /v1/incidents/stream for SSE. News and Buff require authorized server-side credentials.

i

Interactive requests use this site's same-origin, read-only proxy because the API does not currently allow browser CORS requests. The proxy only permits public routes, excludes editorial operations, and is rate-limited. Code examples call the API directly.

Make a request

TERMINAL
curl -sS https://api.nycalert.ai/health

Audience incident integration

Public requests use GET /v1/incidents and GET /v1/incidents/stream without credentials. Protected audience requests use /v1/audiences/{audience}/incidents and /v1/audiences/{audience}/stream through an authorized backend. Choose an audience and review access requirements.

Base URL

All routes are relative to https://api.nycalert.ai. Request parameters are URL-encoded query strings.

!

Only rely on response fields explicitly documented for each endpoint. Some operations currently have unspecified response schemas; inspect their returned JSON instead of assuming a shape.

GETTING STARTED

Authentication & SSO

Public REST and SSE require no API key. Credentials for protected audiences belong on a trusted backend; selection alone never grants access.

i

Public is available anonymously. News and Buff remain locked until server-side authorization and verified credentials are configured. A denied protected request never silently falls back to the public feed.

What is verified

The 2026-10-22 integration guide confirms public, buff, and news. Live OpenAPI declares an authorization header on both audience routes. Its exact value scheme is not documented: do not assume Bearer, an API-key header, or OAuth scopes. An optional header declaration does not mean anonymous access is authorized.

Backend access flow

  1. Verify the user's session with your chosen identity provider.
  2. Map that verified identity to server-side audience entitlements.
  3. Authorize the requested audience on every REST request and SSE connection.
  4. Attach the matching audience credential only on the backend; reject mismatches.
  5. Disable private response caching and audit access without recording tokens or incident payloads.

SSO is an application integration, not a confirmed native NYCAlert endpoint. No identity provider, login flow, or token transport is enabled by this documentation site.

Keep credentials secure

Never put audience credentials in JavaScript, HTML, localStorage, URLs, or copyable browser requests. Future backend configuration may use NYCALERT_AUDIENCE, NYCALERT_AUTH_HEADER_NAME, and NYCALERT_AUTH_HEADER_VALUE; those variables do not unlock this portal today.

Contract and verification status

  • Verified in live OpenAPI: both audience routes, REST limit 1–100 (default 20), an authorization header, and a nonnegative SSE since_id parameter.
  • Confirmed by the guide: audience IDs public, buff, and news; autonomous evidence-validated publication; audience credentials stay server-side.
  • Updated access behavior: public is anonymous by default. Live checks confirm /v1/incidents and /v1/incidents/stream return HTTP 200 without credentials. Explicit /v1/audiences/public paths currently return HTTP 404, so the public selector uses the working unscoped routes.
  • Observed in the guide: incident.created, numeric event IDs, and heartbeat delivery. These observations are not a complete event or response schema.
  • To verify with authorized access: exact credential value scheme, per-audience response shapes, replay behavior, cross-audience isolation, rejected/held-event exclusion, heartbeat interval, rate limits, CORS, and any additional filters.

Do not assume audience roles have particular priorities, delays, or fields: the guide does not define them. Returned publication timestamps identify published claims; preliminary reports should not be presented as confirmed facts. No human editorial approval is required for live publication.

TERMINAL
curl -N 'https://api.nycalert.ai/v1/incidents/stream?since_id=0'

Browser EventSource

EventSource reconnects automatically, but browsers only dispatch event names with registered listeners. This console uses a streaming fetch parser to observe both default and named events.

JAVASCRIPT
const source = new EventSource(
  'https://api.nycalert.ai/v1/incidents/stream'
);
source.onmessage = ({ data, lastEventId }) =>
  console.log(lastEventId, data);
source.onerror = () =>
  console.warn('Stream disconnected; EventSource will retry.');
